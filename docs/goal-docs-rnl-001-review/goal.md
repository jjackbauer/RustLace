## User request (verbatim excerpts defining the deliverable)

> ## **Finding 1 — Exact model values are lost during construction**
> **Required correction:** Model-construction records must preserve exact rational fields, and the
> parser must consume those authoritative exact values. Decimal projections should be used for
> display, not as the sole storage or transport representation of mathematical models.
> Add an end-to-end regression using `1/97` through `sys_station → sys_open → sys_analyze`, and
> another through `sys_closed → sys_mva`.

> ## **Finding 2 — The architecture checker has detection gaps**
> **Required correction:** Add regression fixtures for split implementation blocks, generic
> arithmetic trait implementations, free-function kernels, and renamed numerical representations.
> Where syntax analysis becomes unreliable, use a proper Rust syntax parser or a conservative
> review-required diagnostic.

> ## **Finding 3 — Required CI jobs are not the same as required merge checks**
> **Required operational action:** Configure the relevant checks as mandatory using branch
> protection or a ruleset, and verify that a failing architecture check actually prevents merging
> into `main`.

> ## **Finding 4 — Whole-crate exemptions undermine the single-owner policy**
> **Required correction:** Replace whole-crate exemptions with abstraction-specific ownership.
> `lovelace-rational` may define the canonical `Rat`; that does not imply `lovelace-lang` or
> `lovelace-real` may define another one.
> The mutation suite should deliberately introduce a duplicate rational type inside an otherwise
> legitimate numeric-owner crate and require the checker to reject it.

> ## **Finding 5 — Arithmetic budgets are checked after allocation**
> **Required correction:** add conservative preflight growth estimates, checks within expensive
> numerical operations, and cancellation coverage for long-running normalization.

> ## **Finding 6 — Architecture exceptions are too easy to broaden**
> **Required correction:** require narrowly specified paths, disallow broad wildcard waivers for
> foundational rules, and enforce review ownership through GitHub's protected-branch workflow.

> ## **Finding 7 — Smaller documentation and repository issues**
> The benchmark documentation describes multiplication and division as approximately twice as fast.
> Its actual figures support that description for multiplication, but not division ... Addition also
> measures slower ... The PR also includes `tools/__pycache__/check-architecture.cpython-312.pyc`.
> Remove the generated bytecode file and exclude Python cache directories through `.gitignore`.

> **My merge conditions would be:**
> 1. **P0:** Preserve exact rational inputs through `sys_station` and `sys_open`/`sys_closed`,
>    including long-period fractions.
> 2. **P0:** Replace whole-crate numeric-owner exemptions with abstraction-specific enforcement.
> 3. **P1:** Strengthen the checker against generic and split `impl` declarations, and extend its
>    mutation tests.
> 4. **P1:** Ensure architecture checks actually block merges through repository protection.
> 5. **P1/P2:** Improve resource-budget enforcement, exception scoping, benchmark wording, and
>    repository hygiene.
